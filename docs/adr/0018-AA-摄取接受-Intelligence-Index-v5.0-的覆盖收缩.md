# ADR-0017：AA 摄取接受 Intelligence Index v5.0 的覆盖收缩

- 状态：已接受
- 日期：2026-10-28
- 决策人：owner（会话指令「这个问题修复一下」）

## 背景

2026-10-28 定时刷新起，AA 刷新失败，界面提示「正在使用有日期标记的历史缓存」，缓存记录
的错误是 `源站数据疑似不完整：有效模型从 704 条降为 77 条，拒绝替换缓存`。同一轮刷新里
Arena 与 LiveBench 成功，全程 13 秒——不是网络问题，是摄取契约失效。

manifest 管道全程正常（HTTP 200、manifest 命中、AES-GCM 解密成功），载荷本身完好：

- 仍是 715 个配置，`isOpenWeights` 715/715 完整，契约闸门（≥100 条、≥90% 有开放
  权重标记）全部通过。
- 但 `intelligenceIndex` 只有 77 个是数字，638 个是 null（442 个本就 deprecated，
  196 个仍是当前模型）。
- 页面内嵌的 `initialModels` 同形：272 个当前模型，76 个有分、196 个为 null。

官方口径文字从 v4.3.2 的 10 项评测换成 v5.0 的 9 项：

|      | v4.3.2（10 项）                                                                    | v5.0（9 项）                                                                            |
| ---- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 保留 | AA-Briefcase v1.1、AutomationBench-AA、Terminal-Bench 4.0、GDP.pdf、AA-Omniscience | AA-Briefcase v1.1、AutomationBench-AA、Terminal-Bench 4.0、GDP.pdf、AA-Omniscience v1.1 |
| 删除 | GDPval-AA v2.1、SciCode、Humanity's Last Exam、CritPt、AA-LCR v1.1                 | —                                                                                       |
| 新增 | —                                                                                  | FrontierCode 2.0、HLE-Diamond、CritPt v2（Hard Subset）、Terminal-Bench-Science 0.1     |

用原始基准分做的两步拟合证明**底层评测没动、只有公式换了**：

- v5.0 的 10 个原始键线性拟合今天的指数：R² = 0.9995。
- v4.3.2 的 11 个原始键线性拟合 10-27 缓存里的分数：R² = 0.9988。
- 把同一批原始分按 v4.3.2 权重重算，与 10-27 缓存的平均绝对误差 0.275 分。

后果是整榜重排：77 个两版都有分的配置里 67 个下降、平均 −7.5 分，52 个变化超过
5 分。Step 5 Preview 从 43.7 掉到 28.5——它在被删的 5 项上 z = +0.59，在新增的 4 项上
z = −0.62，新公式不再奖励它擅长的、开始惩罚它弱的。

store 里的跌幅闸门（三榜通用）按「有分条数」比对，把这次源站口径收缩误判成抓取不完整。

## 决策

**接受 v5.0 数据，完整性闸门的比对信号从「有分条数」改为「载荷条数」。**

- 载荷 715 条一条没少，缺的只是指数本身。拒绝替换只会让界面长期停在 v4.3.2 口径、
  和源站对不上，比接受更糟。
- 闸门原本要防的「源站只下发部分数据」仍能被载荷条数抓住：ADR-0006 举的「只下发
  当前模型 273 条」场景，条数同样会塌。
- 「有效分不足 5 条」的底线闸门不动，仍然挡空响应和挑战页。
- 指数版本写进 `sourceDate`（界面标签本来就是「源站版本 / 更新标签」）。v4.3.2 与
  v5.0 的分数不可比，不记录版本就无法判断一批数字是哪个口径。

不触碰融合口径（名次百分位 + 算术平均、成本几何平均），不涉及 ADR-0003。

## 后果

- AA 有分配置从 704 掉到 77，融合榜里 AA 的覆盖面大幅收缩。这是源站真实覆盖，不是
  数据退化。
- 界面「N 条源站模型配置」仍按载荷条数计（AA 仍是 715），不按有分条数计；要看覆盖面
  得看榜单本身。这是已知的展示取舍，不为它新增字段。
- 源站再改版时，AA 依赖「manifest 正则 + 指数版本标题正则」。两者都不是官方承诺的公开
  API，因此闸门与明确报错比「猜新结构」更重要。
