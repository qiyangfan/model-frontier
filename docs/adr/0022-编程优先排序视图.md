# ADR-0022：编程优先排序视图

- 状态：已接受（2026-11-11）
- 关联：扩展 [ADR-0020](0020-性价比决策层改为完整榜单.md) 的榜单展示；池资格口径沿用 [ADR-0021](0021-性价比池资格改纯综合锚.md)

## 背景

owner 使用场景以编程为主（后端 + 编程所需的终端/代理操作），要求「尽量以 coding 为准，但不能牺牲榜单广度」。综合锚已确立（ADR-0021），但综合分中编程只占有限权重（LiveBench 编程仅为其分类之一，Vals 经济任务等与场景无关的轴占坑）。

## 数据事实（2026-11-11 快照）

- 四榜中仅 LiveBench 携带能力分项：`suites`（编程 / 长程代理 / 浏览器操作 / 推理 / 数据分析 / 研究 / 设计），代表行已随 aggregate 透传（`selectRepresentative` 返回原始行），API 零改动。
- 部分配置缺分项（如早期快照中 Wonder/GLM 5.3 Flash/Step 5 Preview 缺编程分项）；缺 LiveBench 整榜的模型（含综合分最高的 Claude Fable 5.2）无任何编程数据——**编程数据覆盖天然不全，广度约束必须靠展示规则保证**。

## 决策

1. **同一榜单双排序切换**（「综合性价比 / 编程优先」Segmented，纯前端显示状态、不持久化）：编程排序按**编程分**降序——LiveBench「编程 / 长程代理 / 浏览器操作」三轴均分百分位（各轴相对有该轴实测的模型总体，`percentile` 同刻度 0~100）。三轴选取对应 owner 场景（后端编码 + 长程代理 + 终端/浏览器操作）。
2. **广度规则**：缺编程分的模型沉到所在段末尾、以「—」标注，保持综合性价比序——未实测不参与比较，也不消失。
3. **诚实边界**：编程口径无市场斜率校准（λ=10 的校准对象是 composite 刻度，不可平移），**不产出调整分、不参与认证加冕**——「首选」徽章仅在综合性价比排序显示；编程视图说明文案如实声明。
4. 融合排名、CSV、分享链接、服务端 API、池资格（4/4）完全不变。

## 备选与取舍

- 用编程分重算调整分（λ 平移）：校准不可迁移，属伪造校准，否决。
- 独立编程卡片：与综合卡片并列会重复两段结构且暗示两个「首选」，违背单一答案原则，否决。
- 扩摄取（AA 分项页 / Vals 编程基准 / Arena 编程切片）提升编程广度：登记为未来选项，当前不做（AA 已有脱离抓取的 ADR-0006 前科，风险大收益不确定）。

## 后果

- 编程视图内综合首选可能不在编程榜首（如 2026-11-11 实测：编程第 1 = GPT-6 Astra 94，综合首选 Gemini 4 Carbon 87 排第 3）——信息分化是本视图的价值所在。
- 新增纯函数 `codingIndices`（三轴均分百分位，任一轴缺失即 null）与 `valueRanking` 的 `view` 参数；Segmented 视图状态不持久化（刷新回综合视图，可接受）。
