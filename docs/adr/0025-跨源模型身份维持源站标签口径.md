# ADR-0025：跨源模型身份维持源站标签口径（不合并异写家族）

- 状态：已接受（评估后维持现状，不改代码）
- 日期：2026-11-24
- 授权：用户把「AA 与 Arena 的家族拆分是否合并」交由此代理判定（会话指令「关于这个你自己判定」）。

## 背景

AA 与 Arena 对同一模型使用不同标签：AA 用「Claude Opus 4.5」「GPT-6 Sol (max)」，Arena 用「Claude Opus 4.5 (20251101)」「Claude Opus 4.5 (High, 32K, 20251101)」。当前 `familyKey`（`server/identity.mjs`）只剥离纯推理档位括号与尾部档位，保留发布日期、产品面与上下文标注，因此这类同名异写会被拆成两个家族。需要判定是否调整身份口径做跨源合并。

## 证据（2026-11-24 实机快照；Arena 源站版本 2026-11-22）

| 指标                                                       | 值                              |
| ---------------------------------------------------------- | ------------------------------- |
| AA 载荷配置 / 家族                                         | 766 / 531                       |
| AA 有分配置 / 当期（非估算、非历史）配置                   | 158 / 127（70 家族）            |
| Arena 行 / 家族                                            | 427 / 408                       |
| AA∩Arena 家族（严格键）                                    | 148                             |
| Arena 独有家族                                             | 260                             |
| 其中与 AA 行「松匹配」成对（去括号、去 preview/chat 等词） | 99                              |
| 上述配对中 AA 侧有有限分                                   | 2                               |
| 上述配对中 AA 侧有当期有限分                               | 1（该命中为假配对；合法配对 0） |
| AA 当期有分且无 Arena 的家族                               | 35（0 个有合法配对）            |

「松匹配」是诊断口径：去掉全部括号、去掉 preview/beta/chat 等词与推理档位后比较，未进入产品代码。基于它得到的关键事实：

1. **计分收益为零。** 99 对异写里 97 对 AA 侧分数为 null（v5 未评），合并不改变任何榜单可用性；剩下 2 对中，`Command A (03-2025)` ↔ AA `Command A+` 是假配对（A 与 A+ 是不同模型），只有 `Gemini 3.1 Flash-Lite Preview` ↔ AA `Gemini 3.1 Flash-Lite`（6.2 分、历史）会产生一次真实计分变化——把一个历史低分模型拉进两榜池。
2. **反向影响也为零。** AA 当期有分且无 Arena 的 35 个家族里，没有任何一个存在合法的松匹配对象（唯一命中仍是 Command A+ 假配对）；合并不会给主榜补进任何当期模型。
3. **历史条目并非完全无关。** 融合的榜单可用性只排除估算，默认不排除历史（「排除历史配置」默认关闭；58 个两榜家族里 14 个的 AA 代表是历史条目）。因此合并若命中历史但仍有分的条目，会直接改变主榜成分——这是保持保守口径的另一个理由。

## 决策

**维持现行身份口径**：跨源家族只在「源站标签去掉纯推理档位后一致」时合并；发布日期、产品面（Chat/Instant）、上下文标注保留在身份里。不同写法视为两个家族，各自携带各自的单榜证据，不共享投票。本次不改代码。

## 备选方案对比

| 方案                                   | 复杂度 | 计分收益                                  | 兼容/迁移                                                          | 长期维护                                   | 结论 |
| -------------------------------------- | ------ | ----------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------ | ---- |
| A 扩展 familyKey 自动剥日期/上下文括号 | 低     | ≈0：仅 +1 个历史低分模型，另 1 对为假合并 | 家族 id 变化会让分享链接的模型选择、历史指纹与本地选中断链，需迁移 | 名称语法随源站命名持续膨胀，每改版都要跟修 | 否决 |
| B 人工跨源别名登记表                   | 高     | 库内整洁，计分仍 ≈0                       | 需逐条迁移并全量回归                                               | 60+ 厂商随新模型持续维护，与小工具定位冲突 | 否决 |
| C 维持现状 + 口径文档化（本 ADR）      | 零     | 0                                         | 无                                                                 | 无                                         | 采纳 |

方案 A 的假合并案例（同一条松匹配规则下真实存在）：

- `GPT-5.2 Chat (20260210)`（Chat 产品面）↔ AA `GPT-5.2`（API 模型）——不同产品与评测协议会被并成一票。
- `Llama 3.1 405B Instruct (FP8)`（量化 Instruct）↔ AA `Llama 3.1 405B`（基础模型）。
- `Command A (03-2025)` ↔ AA `Command A+`——A 与 A+ 是不同模型，松匹配已经误配。

这些都属于「把不同实验视为统一实验」，违反宪法第 1 条诚实性红线与单榜脚注既有口径（不同任务协议和推理配置不能视为统一实验）。

## 已知限制与触发条件

1. `familyKey` 删除所有非字母数字字符，`Command A+` 与 `Command A` 当前被并成一个家族（A+ 有当期分 6.2，A 已历史且无分，暂无计分影响）。触发修复条件：一对仅差「+」的名字同时携带当期有效分时，改为保留「+」（或映射为 plus），并处理旧家族 id 在分享链接与本地选择中的兼容。
2. 若源站未来提供官方统一模型 id 或别名映射，按官方 id 合并优先于名称语法——届时另立 ADR。
3. 模型库中同名异写各占一行（例如 AA「Claude Opus 4.5」与 Arena「Claude Opus 4.5 (20251101)」），这是按源站标签保留证据的预期行为，不是重复数据。

## 影响与兼容

- 代码零变更；不改综合分、PK 准入、缺榜罚分、分享契约或 CSV 列。
- 无数据迁移；历史抽屉与三套 E2E 均不受影响。
- 后续评审此议题时直接引用本 ADR 的实测数字，不再重复推导。
