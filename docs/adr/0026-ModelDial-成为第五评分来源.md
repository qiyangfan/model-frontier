# ADR-0026：ModelDial 成为第五评分来源（不进成本源）

- 状态：已接受（2026-11-24）
- 关联：推翻 [docs/source-assessment.md](../source-assessment.md) 中「ModelDial 不纳入」的 2026-10-19 结论；评分基座沿用 [ADR-0011](0011-多数对决投票制.md)/[ADR-0013](0013-Arena-成为第四票.md)/[ADR-0023](0023-性价比榜单准入对齐天梯与历史校准缺榜罚分.md)

## 背景

owner 提出把 ModelDial（<https://modeldial.com/en>）纳入调研。此前 `docs/source-assessment.md` 只评估过 HF Open LLM、HELM、Epoch ECI 三个候选并全部否掉，ModelDial 从未被评估过——不是被否掉，是没看过。本次补齐。

ModelDial 是公开只读的第三方评测站，三个榜：Coding Rankings（编程能力）、Text Capability Rankings（中文写作）、Harness Rankings（排 harness 工具而非模型）。站点无账号、无 API key，数据以 JSON 端点公开，`/data-license` 声明 Coding 榜数据按 CC BY 4.0 发布，`/openapi-v1.json` 提供 OpenAPI 3.1 描述。

owner 给出的需求口径：**工程能力为主、后端权重高于前端，同时覆盖工具调用、分析、出方案、debug、重构、终端操作**。据此逐项核对四个既有来源：

| 需求维度        | Artificial Analysis  | Vals       | LiveBench                                                   | Arena      | ModelDial                                                          |
| --------------- | -------------------- | ---------- | ----------------------------------------------------------- | ---------- | ------------------------------------------------------------------ |
| 后端 / 前端     | 折成一个「智能指数」 | 无         | 有 `coding` 轴，前端形态散在 `design` 轴（ADR-0022 已排除） | 无         | **独立 `backend` 轴（权重 30%，最大单项）+ `frontend` 轴（15%）**  |
| 重构 / 调试     | 折成一个分           | 无         | 无                                                          | 无         | **独立 `maintainability` 轴（15%），专测改造成本、故障恢复、诊断** |
| 分析 / 推理     | 折成一个分           | 无         | `data_analysis` + `reasoning`                               | 无         | `knowledge` 轴（25%）                                              |
| 工具调用 / 终端 | 折成一个分           | 无         | `long_agentic` 轴（最接近的一项）                           | 无         | 无                                                                 |
| 人类偏好        | 无                   | 无         | 无                                                          | 有（专长） | 无                                                                 |
| 业务流程        | 无                   | 有（专长） | 无                                                          | 无         | 无                                                                 |

ModelDial 是五个来源里**唯一**有独立后端轴和独立可维护性轴的，正对 owner 需求里最重、也最缺数据的两块。LiveBench 的 `long_agentic` 是工具调用唯一可用的代理指标，Arena 的人类偏好与 Vals 的业务流程是其余来源都没有的独立信号——这两票即便与编程无关，也不构成摘除理由（见「后果」里的实测代价）。

## 决策

1. **`SCORE_SOURCES` 增加 `modeldial`，成为第五票。** 每对模型共同有效榜单不少于两榜才比赛、每榜一票的 ADR-0011 机制原样沿用，不改任何权重——新增的只是一次独立测量。
2. **ModelDial 不进 `COST_SOURCES`。** 其成本口径是「跑 ModelDial 自己那套私有题库要花多少钱」（版本化 `pricingSnapshotId`），与另三源的「干一个任务花多少钱」不是同一单位语义，混进几何平均会污染成本轴。ADR-0017 已确认成本轴用三源几何平均，此处不扩。
3. **适配器只取 Coding 榜，且取站点声明的「每个模型默认取最高分的完整配置」。** Text 榜（中文写作专项，与项目通用选型目标不同题）与 Harness 榜（排 harness 工具不排模型，且无结构化端点、只能解析 HTML）均不接入。
4. **总分自算，不取站点的 `overall_score` 字段。** 站点 `snapshot.entries` 的五轴分是扁平的 `${axis}_score`，`qualityScores.weights` 给出权重（backend 30 / frontend 15 / knowledge 25 / aesthetic 15 / maintainability 15），加权和即站点展示的 Overall。已用 120/120 条有站点总分的条目反算验证：中位差 0.003 分、P90 0.005 分、最大 0.29 分（仅 1 条超 0.1）。自算而非直读，是为了权重一旦变化能被明确发现（`weights` 为空或总和为 0 直接报错），而不是静默用旧口径。
5. **三类条目必须剔除**：站点自己标为未发布的 `hiddenModelIds`（9 个 id，命中 14 条快照条目）；`product_kind === "bot"` 的外部产品评测（2 条，评测对象是产品不是模型）；被 `listing_replaces` 顶掉的旧 route（站点用该字段声明「本条顶掉那条」，要剔的是被顶掉的那条）。
6. **缺榜罚分（ADR-0023 的 15 分）移除。** owner 授权用五榜数据重校，三种独立方法都复现不出原依据，实测效果也接近零。详见下文「缺榜罚分为什么被移除」。

### 缺榜罚分为什么被移除（owner 2026-11-24 要求重校）

owner 授权用五榜数据重校，原话：「可能变 10，也可能变 20，也可能删掉，毕竟当时的 15 也是调研出来的」。跑了三种互相独立的方法，**没有一种能复现 ADR-0023 的「每补一榜综合分漂移均值 −15.4」**：

- **留一榜法（当前五榜快照）**：只对原本五榜全齐的 22 个模型做，n=110。去掉任意一榜，综合分漂移均值 −7.43、中位 −5.23、|漂移| 中位 24.86。分轴看 AA 最大（−19.5）、ModelDial −11.0、LiveBench −5.6、Arena −1.7、Vals +0.6。对原本四榜的 14 个模型 n=56：均值 −11.53、中位 −14.45。
- **历史覆盖增长事件法（`data/history.json` 全 60 条）**：n=70 次事件，综合分漂移均值 **+87.9**、中位 +44.4、|漂移| 中位 82.0；同期覆盖度未变的对照组 n=3422，漂移均值 −1.9、中位 0.0、|漂移| 中位 1.4——差值真实存在，不是全局漂移。按增长前覆盖分档：2→3 榜 n=25 均值 +103.0；3→4 榜 n=45 均值 +79.6。
- **横截面**：五榜下有综合分的 65 个模型，综合分中位数 5 榜 1312 / 4 榜 936 / 3 榜 597 / 2 榜 679。覆盖越少分越低，但这是选择效应（大厂模型上的榜多且确实强），不能当因果读。

**测不出稳定常数的机制原因**（这不是统计噪声，是设计使然）：`src/analysis.mjs:170` 的对局成立条件是 `sharedSources >= 2`。一榜不只是多一票，它决定这个模型**能不能跟某个对手比赛**。去掉一榜会让一批只共享那一榜的对局整条消失，所以「缺一榜的影响」取决于缺哪一榜、模型原本覆盖几榜，本身就不是单一常数。这正是 ADR-0023 自己披露的不确定性也很大（|漂移| 中位 23.4，均值标准误 ±32）的原因。

**敏感性**：罚分 = 0 / 10 / 15 / 20 时性价比榜前 15 名几乎相同（只差 1 个条目）；罚分 = 30 时才让第 10 名换人。这个数对头条结论不承载。

**结论：删掉，不是换一个数。** 三个理由：

1. 依据不可复现。换成 10 或 20 只是用一个新拍脑袋替掉旧拍脑袋；删掉则让公式里只剩可追溯的项。
2. 实测无效。前 15 名只差 1 个条目；覆盖 ≤3 榜的模型名次移动 ≤3 位，且始终在第 17 名以后。
3. 它的本意（防缺榜高估）已由拟合本身实现：缺一榜直接减少可比对手（共同有效榜 <2 不配对），低覆盖模型天然落到榜尾。数据上，五榜全齐的前几名综合分 1548/1532/1516，覆盖最少的模型最高 1303，差 200 多分。罚分是同一作用上的第二道闸。

`src/analysis.mjs` 的 `MISSING_BOARD_PENALTY` 常量、`adjustedScores` 与 `certifyNoBrainer` 里的罚分项、相关注释与测试用例一并删除。调整分公式回到 `composite − λ·log2(cost/100)`；λ=10 仍然有可追溯依据（ADR-0019 的三榜交叉 21 模型实测市场斜率 9.4±2.7/翻倍）。覆盖面不再折算成分数里的暗项，改为直接展示（Portal 的 N/5 榜、对比页的共同有效榜）。

若将来低覆盖模型真的挤进性价比榜头部，正确的处置是拿当批数据重新做一次可复现的校准再立 ADR，而不是恢复这个常数。

## 后果

- **排名与契约**：有综合分的模型 58 → 65 个；性价比榜入榜数 42 → 42，无新进（ModelDial 独有
  的 12 个模型没有 COST_SOURCES 成本，进不了性价比榜）。名次上升 12、下降 11、不动 19。
  最大移动：GPT-6.2 Sol 12→6、GPT-6.1 Sol 11→8、Gemini 4 Argon 5→11、Gemini 4 Hydrogen
  7→12。综合排名、性价比层、罚分公式、分享链接均不变；CSV 追加在末尾两列 ModelDial 分与配置，
  并多一档「双方共有 5 个有效评分榜的对局数」（插在原有三档与位次均值列之间）。

- **顺手收敛的两处「源数写死」**：
  1. `src/presentation.mjs` 的 `NAMES` 原本是硬编码四键对象，而 `src/portal.mjs:3` 的
     `SOURCE_IDS = Object.keys(NAMES)` 被当结构用（`src/portal.mjs:159-160` 的
     `Array(SOURCE_IDS.length + 1).fill(0)`）。源数变 5 而 NAMES 仍是 4，覆盖分档数组会短
     一截。现改为从 `shared/sources.mjs` 的 `SOURCE_NAMES` 派生，加票只有一处要改。
  2. `server/adapters.mjs` 的 `SOURCE_INFO` 各源原本自带 `name`，现改为从 `SOURCE_NAMES` 派生。
- `server/identity.mjs` 的 `preferred` 兜底链补 `representatives.modeldial`：不加则
  ModelDial-only 模型组会让 `preferred.name` 抛 TypeError。
- 界面文案「四榜/四源」→「五榜/五源」共 13 处。

### 缺榜罚分（ADR-0023 的 15 分）在本次接入时重新校准并移除

罚分的复算、机制解释与删除理由见上文「缺榜罚分为什么被移除」，此处只记接入后与罚分相关的实测变化。

- **有综合分的模型 58 → 65**；性价比榜入榜数 42 → 42，**无新进**——ModelDial 独有的 12 个模型没有 `COST_SOURCES` 成本，进不了性价比榜（`adjustedScores` 要求成本有限且为正），只影响融合排名与 CSV。
- 名次变化：上升 12、下降 11、不变 19。最大移动：GPT-6.2 Sol 12→6、GPT-6.1 Sol 11→8、Gemini 4 Argon 5→11、Gemini 4 Hydrogen 7→12、Grok 4.7 25→22、Kimi K3 33→29、MiniMax-M3.1-Flash 30→27。
- **五源覆盖度分布**：5 榜 22 个、4 榜 14、3 榜 9、2 榜 20。缺榜罚分已移除（见下节），覆盖度只作展示。
- 界面与 CSV 文案中的「四榜」统一改为「五榜」；`certifyNoBrainer` 的 λ 扫描与 `src/main.jsx:538` 的方法说明随之更新。
- **CSV 列结构变化**：新增 ModelDial 分与配置两列（追加在原有四源列之后）；「双方共有 N 个有效评分榜的对局数」档位由写死的 2/3/4 改为从 `SCORE_SOURCES.length` 派生，本次多出第 5 档。档位列的位置在原有三档之后、位次均值列之前。
- **Vals 与 Arena 保留**。实测代价：若摘掉这两票，有排名模型 58 → 43，掉出的 20 个正是便宜档（Granite 4.2 3B/8B/30B、Gemini 3.5 Flash-Lite、gpt-oss-120b、Mistral Medium 3.5、Solar Pro 4、Qwen 3.8 Max 各档、Inkling Small、Beam 1.0、Muse Ember/Glimmer、Wonder Full，外加 Claude Opus 4.8 max、DeepSeek V4 Pro/Flash high、GPT-5.6 Sol low 等推理档位变体）。这两票虽然与编程无关，但是「便宜模型也能上桌」的主要证据来源，摘掉会让榜只剩前沿模型，毁掉工具的核心用途。加权降权方案同时被否：任意倍数是不可审计的数字，违背可复核性，且 owner 自己就因「操纵榜单的嫌疑」从加权退回过平权。
- **数据纪律**：`data/snapshot.json` 的 `sources` 新增 `modeldial` 键；`tests/store.test.mjs` 的键集合断言、`tests/majority.test.mjs` 的夹具、`tests/analysis.test.mjs` 的罚分用例随罚分移除一并删除。所有来源数量都改为从 `SCORE_SOURCES` 派生，不再硬编码——下次加票不必回来逐个改数字。
- **新增测试**：`tests/adapters.test.mjs` 覆盖 ModelDial 五轴加权自算、每模型取最高分配置、未发布模型与 bot 剔除、`listing_replaces` 语义（顶掉的是被声明的那条，不是声明的这条）、轴分非数字时整条剔除而非按 0 收、权重缺失/为零/结构漂移报错。
- **已知局限**：ModelDial 的 `aesthetic` 轴（15%）测界面美观，对「全栈开发」视角是偏靶轴。本 ADR 不为此重设权重（自设权重即不可审计），该信号以原始五轴之一的形式进入投票，与其他四票同权。若将来要收窄，须另立 ADR。
