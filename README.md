# 模型观测台 · Model Atlas

[![CI](https://github.com/qiyangfan/model-frontier/actions/workflows/ci.yml/badge.svg)](https://github.com/qiyangfan/model-frontier/actions/workflows/ci.yml)

本地 React + Ant Design + ECharts 四榜融合工作台，样式用 Tailwind v4 工具类（`src/style.css` 为 Tailwind 入口 + antd 覆盖等残余层）。直接读取 Artificial Analysis、Vals、LiveBench、Arena 的公开数据，自动发现模型，重点展示开放权重模型，不维护模型关注白名单。

## 四榜融合功能

LiveBench 分数按现有 ADR 对可用分类取等权均值；当前源站 Overall 对部分分类加权，因此两者不能直接等同。

- **综合总览**：全球与开放权重领先模型、全量模型覆盖分布和各站同步状态。默认进入总览。
- **融合排行榜**：PK 主积分（Bradley-Terry / Elo）与成本披露分离，没有成本的模型仍可参与排名；可搜索、按厂商和开放状态筛选、按分数排序，并导出当前筛选结果。可打开「LiveBench 能力维度」列按编程、推理、研究等分类原始分排序（仅 LiveBench 提供维度，缺失保持空白）。排行榜与前沿探索的模型表另有「厂商快捷筛选」chip：Anthropic、Google、Meta、OpenAI、MiMo、DeepSeek、GLM、Kimi、Step、Qwen 等代表性前沿厂商一键定位，与厂商下拉同源、只改变显示，完整厂商列表始终保留在厂商下拉与搜索中。
- **单榜模型库**：在排行榜内切换 AA、Vals、LiveBench、Arena，保留各站全部配置，按原始总分排名。默认排除历史 / 估算配置，可分别启用；有分无成本仍排名。原始总分无效的配置保留但不赋名次。Arena 单榜展示官方原始偏好评分，并随行显示盲测投票数、源站评分区间与榜单发布日期。
- **模型对比**：从融合榜勾选或从详情、搜索添加 2–4 个模型。展示四榜排名百分位、原始分、每站任务成本、配置、AA token 价格与速度 / 延迟，以及 LiveBench 分类原始分与 Arena 票数 / 区间 / 发布日期；选择保存在本机。
- **预算约束筛选**：在评分口径面板选择某一来源并设定每次任务美元成本上限，超预算模型与未披露该来源成本的模型从列表和前沿图中隐藏；只改变显示，不改变分数、名次与前沿。预算与成本口径仅限 AA、Vals、LiveBench 三个任务成本来源，综合相对成本继续用于跨源观察，不充当美元预算。
- **前沿探索**：保留二维帕累托与独立开放权重前沿，可切换成本来源比较。悬浮任一全球前沿模型，即标出它同时以更低成本、更高 PK 主积分支配的区域及其中模型数；被支配模型的悬浮提示反向列出支配者，详情抽屉给出完整支配关系。
- **数据来源与刷新**：四站后台 HTTP 定时抓取、失败回退、来源日期及原始配置追溯。

排行榜、对比与前沿统一使用四榜多数对决拟合的 Bradley-Terry 强度；双方至少共有两个有效评分榜才比赛，PK 主积分相同时再按辅助分排序。BT 按对手强度校正赛程，显示为 Elo 尺度（中位 1000，400 分差约等于 10∶1 预测胜率）。排行榜中的战绩提示可查看双方共有不同数量有效评分榜的对局分布；该分布只描述样本覆盖，不改变对局定义。排名百分位由同一综合样本计算。显示筛选不改变分数和已有名次；单榜原始分不直接跨榜相加。单榜视图的历史 / 估算配置开关仅控制该单榜视图，不影响融合评分。

支持 `#overview`、`#rankings`、`#compare`、`#explore`、`#sources` 页面地址，刷新后保持所在页面。「复制分享链接」把当前估算与质量排除开关、成本口径、预算筛选、排行榜筛选、榜单组合对照选择和对比选择写入页面锚点参数（如 `#rankings?cs=vals&cm=aa%2Bvals&eh=1`），打开同一链接即在完全相同口径下复核结论；采用默认设置时省略参数值，但分享链接保留 `?` 标记（如 `#rankings?`），避免沿用接收方偏好。所选组合在当前数据下无法比较时会保留选择并明确提示，不会静默切换到其他组合。「导出 CSV」与「导出当前榜单」均附带数据时间与完整评分口径列，单榜导出另附该来源的获取时间与版本标签，便于日后复核同一结论。页面顶部“导出 CSV”导出综合快照（前沿页应用该页显示筛选）；排行榜内“导出当前榜单”导出当前源与筛选结果。

## 使用

当前机器上已安装依赖、构建完毕。双击 **启动模型前沿.command**，浏览器打开 <http://localhost:4317>。若已经运行，会复用现有服务。

普通终端方式（在本目录）：

```sh
npm ci
npm run build
npm start
```

需要 Node.js >= 22.12 和网络。仅监听 127.0.0.1。网页资产已本地打包，运行时不从 CDN 下载组件。

首次启动（或数据目录为空）时页面会先空榜几十秒：服务在后台抓取四站，抓完自动落盘生效，之后按刷新间隔定时更新。数据只写本地磁盘、不进 git（见 `docs/adr/0007`）。

- `npm run dev`：开发模式，同样使用 4317 端口，与生产模式二选一。
- `npm run refresh`：独立执行四站抓取并写入缓存；不要与正在运行的服务同时执行。日常使用网页“从源站刷新”即可。
- `npm test`：解析器、模型身份、排名、前沿、缺失处理、缓存回退与并发刷新测试。
- `npm run test:portal`：五页导航、单榜切换、筛选导出、对比持久化和移动布局的端到端验证。使用本机无头 Chrome，仅供测试。
- `npm run test:e2e`：服务运行后检查桌面/手机布局、预设、详情、导出、错误提示和设置接口。使用本机 Chrome。

## 自动更新

默认本地服务运行期间每 6 小时刷新，可在网页改为每小时、每天或关闭。启动时缓存到期会补更。无需 API key 或 Codex 会话。已有刷新间隔设置会保留。

Arena 文本总榜取自官方 Hugging Face 数据集 `lmarena-ai/leaderboard-dataset` 的单文件 Parquet 快照（`text / latest / overall`，ADR-0013），提供人类盲测偏好评分、票数、区间与发布日期；不将其余分类重复计票。旧格式 Arena 缓存不作为成功观测，启动时会清理并重新获取。这里使用各站公开数据，并非承诺存在统一官方 API。

四站均通过后台 HTTP 读取公开页面、内嵌结构化数据、CSV 与 Parquet。运行和定时刷新不依赖浏览器，不会启动 Chrome；源站拒绝时保留最后成功缓存并显示原因。服务关闭或电脑休眠时不继续刷新，下次运行补更。

数据目录可用 `FRONTIER_DATA_DIR` 覆盖，端口可用 `PORT` 覆盖（双击启动器固定 4317）；`FRONTIER_AUTO_REFRESH=0` 关闭自动源站刷新（供离线演示与确定性 E2E）。

`data/snapshot.json` 保存源站原始配置行、成功获取时间、最近尝试时间、错误、发布标签和刷新间隔。单站失败独立回退；少于 5 条的异常响应不替换缓存。手动刷新与自动刷新共享执行锁，同进程内不会重复抓取。

## 权重与计算

默认采用**四榜各一票的多数对决 + Bradley-Terry 强度（BT）**，评分来源为 AA、Vals、LiveBench、Arena（ADR-0013、ADR-0015）。至少两个榜单有效的模型准入，双方共同有效榜单至少两个才进行对决。每对模型按各榜原始分逐榜投票，领先榜数更多者赢一场，同数则平局；四榜 2∶2 时该场判平。所有有效对局作为一个全局配对样本，用 BT 模型（平局半胜，Gamma(2,1) 弱先验）估计相对强度。

`PK 主积分 = 1000 + (400 / ln 10) × (θ − 中位θ)`，其中 `θ = ln(强度)`；中位模型为 1000，400 分差约等于 10∶1 预测胜率。

主榜始终是单一全局榜；BT 按对手强度校正赛程，不会因只打弱对手而抬高胜率。对局图不连通时不给出跨组件全局名次，也不回退到旧公式。主榜还要求至少 10 个有效对手（双方共同至少两榜的对局）；低于门槛的模型保留原始分、配置、胜平负、胜率和对手数，但不赋主榜名次、不参与前沿，其比赛仍进入 BT 拟合。门槛依据见 ADR-0016；当前快照所有有分模型至少 20 个对手，因此现有榜单不变。PK 主积分相同才按已有榜单排名百分位（含 Arena）的等权平均排序；位次均值只作同分排序，不作为第五票、不与主积分再次合并，也不参与帕累托判定。主辅分均相同则并列。共同榜单不足两榜的对决不计入分母，没有有效对手时不给分。不足两榜的模型仅展示原始分。对手集合可能不同，页面显示实际对手数；BT 不是实测胜率、能力比例或统计置信度。

现行 Copeland 胜率（`100 ×（胜场 + 0.5 × 平场）÷ 对手数`）和名次保留为诊断，只在模型对比与 CSV 中展示，不进入主榜、前沿、同分排序或分享参数。排行榜分别标出 PK 主积分与榜单位次均值及来源覆盖；悬浮战绩中的对手数可查看“双方共有 N 个有效评分榜的对局数”，相同信息也写入 CSV。对比页同时展示共同有效榜数、逐榜票数、原始分、同榜分差，以及 BT 与 Copeland 的方法对照；Arena 行另附盲测投票数、源站区间与发布日期（该区间不是融合置信度）。不跨榜相加原始分，也不引入任意混合比例。可在前沿探索中切换成本来源，直接比较能力与成本取舍。

融合排行榜另提供榜单组合对照：选择一组榜单后，只纳入这些榜单都有有效分的模型，并只用所选榜单在这组模型中重算 BT，再与主榜名次和积分对照。各对照组的 Elo 以该组中位模型为 1000，积分只在该组内比较，不能与主榜数值直接相减。本表是诊断层，不套用主榜的 10 个有效对手门槛；组内对手数见列。榜单和参与比较的模型范围都可能改变，因此结果用于观察排名对比较范围的敏感程度，不能单独说明某个来源的影响，也不替代主榜或代表能力百分比。搜索与筛选只隐藏对照行，不改变对照结果。

仅保留当前一套规则，不维护旧评分公式或版本切换。分享只编码质量排除、估算、成本、预算、显示筛选、同来源对照组合与对比选择；不编码或解析 `score/p/w/ms`。带有这些过时参数的地址仍按当前规则计算，并在同步时清理无效参数。模型数据的历史快照与源站更新记录继续保留。成本算法保持不变（ADR-0012）。

默认横轴是 **综合相对成本（基准 1 倍）**：对三站成本都有效、为正且估算设置允许的固定模型样本，分别求 AA、Vals、LiveBench 任务成本中位数；模型各站成本除以对应中位数，取三个比值的等权几何平均并乘 100。公式为 `100 × ∛[(AA/AA中位数) × (Vals/Vals中位数) × (LB/LB中位数)]`。完整三源时，成本权重各 1/3，与能力权重独立。默认允许至少两源成本：缺一源时对两个有效比值取平方根，等权几何平均，标记 2/3；完整时标记 3/3。中位数基准始终用三源完整样本计算。页面展示值为原指数除以 100，例如 10.1 显示为基准的 0.10 倍，不是美元，不可解读为生产账单；缺失不补值，少于两源不入图。部分覆盖仍有任务分布偏差，显示覆盖数量不能消除这种不确定性：实测池变动时 3/3 与 2/3 覆盖模型的指数漂移幅度平均相差约 1 个百分点（最大 8.6），可能翻转成本轴上相距很近的相邻顺序；该效应在 23 个历史快照中未单独导致过一次跌出前沿，评估与备选方案见 `docs/adr/0017`。中位数与每站明细在模型详情可复算。切换单站成本时，才使用该站的 **每次任务美元成本**。不将三个来源美元成本直接相加。成本缺失、为零或非正不入对数图。LiveBench 的任务成本使用可用类别的总 cost / 总 tasks；详情单榜核对也显示它的每次成功任务成本，两者有明确标记。

主帕累托图直接复用融合榜同次计算的主积分和所选成本，辅助分只排序，不进入纵轴或支配判定。闭源散点与图例使用不透明蓝色，只有主动隐藏的图例降低透明度。

帕累托：不存在另一模型成本不高、分数不低，且至少一项更优，则属于前沿。分别计算全体模型的全球前沿，以及只在开放权重模型中计算的开放前沿。图中连线只引导视线，不表示模型之间可连续插值。

**为什么不同口径下的前沿不同？** 成本来源、推理档位、发布版本和样本交集会改变结果。模型详情展示支配者、综合成本和三种美元成本下的前沿结果，以及单榜完整样本核对，便于定位差异。

**为什么入库一个新模型会让旧模型跌出前沿？** 更贵的新模型不可能直接支配更便宜的旧模型——帕累托要求支配者成本不高且分数不低，23 个历史快照复算中 5 次跌出的支配者 100% 是上期已在前沿的老模型。前沿成员变化来自两个池相对量：主积分按当前对局图重新拟合（新对局就是关于旧模型的新信息，这是 BT 的设计目的），以及综合成本的中位数基准随池重算。中位数平移对同覆盖度模型是同一倍数，不改变它们的相对顺序；2/3 与 3/3 覆盖模型的漂移幅度不同，可能翻转成本轴上相距很近的相邻顺序。若某次跌出既不是自身数据变化也不是支配者数据变化，那是重新拟合的结果，属预期行为。

## 模型身份与开放状态

自动归并采用名称语法去除明确的 inference effort 后缀，保留日期、Preview、Vision 等版本区分；少量明确品牌名称映射用于 Wonder / Muse Wonder 1.0。没有模型准入白名单。未知的新模型也加入并集。无法确认的名称分别保留，因此模型条目总数不等于基础架构的独立数量。

每站代表配置优先选择非估算、非历史条目，然后取最高有效分数；同分时使用已披露的较低任务成本。成本与该条配置绑定，不能将高档位能力配上低档位成本。模型详情保留该站全部配置。

开放权重来源为 AA `isOpenWeights`、LiveBench `openweight` 和 Arena 许可证字段。只依据源站披露，不以中国厂商或模型名字猜测。信息冲突时标记“来源有分歧”，未披露为“未确认”。**开放权重不等于 OSI 认可的开源，也不自动意味着允许任何商用用途**；许可证显示在模型详情。

## 已知边界

- 模型族归并不是统一实验：各站的 effort、工具、测试时间和 fallback 可能不同。部分 Anthropic 分数包含 fallback。
- BT 只使用每场对局的胜负，不使用原始分差；强队之间可能出现循环，等级分是相对强度，不是正确率或能力百分比。主辅分都相同才并列；不给出虚假的置信区间，低覆盖模型的差异应结合对手数与共同榜覆盖阅读。
- 主榜要求至少 10 个有效对手；低样本模型只展示原始战绩，不参与主榜与前沿。该门槛控制的是中位真实强度模型的误入率，不保证任何短全胜记录都不高位。
- 历史 AA 配置保留在发现列表，详情有标记；单榜核对剔除 AA 历史和估算配置。缺失任一榜单的模型仍可在表中找到。
- API 任务成本不能替代本地推理的硬件、显存、吞吐、能源或运维成本。
- 源站页面、Next.js 内嵌字段、CSV 路径或名称规则改变时，适配器可能需要维护。解析失败明确报错，不会静默编造数据。

## 文件结构

- `server/adapters.mjs`：四站真实采集及解析。
- `server/identity.mjs`：模型名称归并与开放状态证据。
- `server/store.mjs`：快照、失败回退、刷新锁和间隔判断。
- `server/index.mjs`：本地 HTTP 服务和自动更新。
- `src/analysis.mjs`：BT 主积分、Copeland 诊断、前沿与单榜核对；可独立测试。
- `src/main.jsx`：统一导航、评分设置、状态与详情。
- `src/Portal.jsx`：总览、融合 / 单榜排行榜和模型对比。
- `src/portal.mjs`：排序、筛选、单榜配置、预算约束、覆盖统计与安全导出。
- `src/share.mjs`：分享链接参数与页面口径状态的编解码。
- `src/CompareChart.jsx`：四榜排名百分位柱状对比。
- `src/Chart.jsx`：ECharts 图表、SVG 图标工具栏与滚轮事件边界。
- `src/presentation.mjs`：相对成本倍数与真实美元价格格式。
- `data/snapshot.json` / `data/history.json`：四榜聚合缓存与历史档案，由服务端刷新写入本地磁盘，不进版本控制（ADR-0007）。

## 图表交互与显示

界面统一使用 Ant Design 组件与 `@ant-design/icons` 的 SVG 图标。滚轮始终用于页面滚动；按住 ⌘ / Ctrl 滚动滚轮（或在画布上捏合触控板 / 触屏双指捏合）时，图表以指针为中心双轴缩放并接管浏览器页面缩放。拖动平移双轴，缩放也可通过按钮和横轴滑块完成，可重置、全屏和下载 PNG。悬浮卡同时列出三站真实美元任务成本，下方基准卡显示各站中位数；成本倍数表示相对基准，并非真实统一账单。探索页搜索只过滤下方模型表，不会从散点图移除点位；命中模型以橙色描边和名称标签标注，便于在完整前沿背景下定位。

## 仓库治理

小型分析页，治理从简，文档全部面向「下一棒读者」：

- `AGENTS.md`：AI 协作命令速查、改动后验证流程与已知坑。
- `CONSTITUTION.md`：不可妥协原则（诚实性红线、显示与评分分离、架构不漂移）。
- `NORTH_STAR.md`：北极星——结论可被任何人在同一口径下复核；附反指标。
- `ROADMAP.md`：已交付 / 点名才做 / 明确不做，不维护愿望清单。
- `docs/adr/`：架构决策记录（单服务不换栈、分享链接契约、量化口径基准、门禁选型）。
- `openspec/`：轻量规格约定，沉淀分享链接与融合评分两项核心契约。

质量门禁：ESLint（`--max-warnings 0`）、Stylelint、Prettier、单测覆盖率阈值（行 92% / 分支 85% / 函数 90%）。CI（GitHub Actions）运行静态检查、带阈值的单测、构建，并用确定性夹具跑三套 Chrome E2E（不访问源站）；真实源站抓取的健康由独立的每日巡检工作流检查（`docs/adr/0014`）。本地交付也必须跑三套 E2E（`docs/adr/0004`）。
