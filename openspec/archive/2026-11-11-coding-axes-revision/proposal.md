> `openspec/specs/ranking/spec.md`（Scenario: 编程优先排序视图）；修订记录见
> `docs/adr/0022-编程优先排序视图.md`。

## 动机

owner 连环质询编程维度构成：为什么含浏览器操作（后端需要浏览器吗）、无浏览器操作实测是否不公平、coding 轴是前端还是后端、agent/长任务/推理/数学是否更代表后端能力。

## 涉及能力

- `ranking`（性价比首选卡片需求——编程优先排序视图 Scenario）

## 行为前后差异

| 维度       | 前                                                | 后                                                                                                  |
| ---------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 编程分组成 | LiveBench「编程 / 长程代理 / 浏览器操作」三轴均分 | LiveBench「编程 / 长程代理 / 数据分析」三轴均分（后端三件套：算法编码 + 长任务代理 + 数据处理/SQL） |
| 卡片文案   | 三轴组成含浏览器操作                              | 同步为数据分析；其余交互不变                                                                        |
| 口径/契约  | —                                                 | 融合排名、CSV、API、全球前沿、快筛全部零改动；编程榜序微调（Carbon 升 #1，头部成员不变）            |

## 决策与证据

- **覆盖层**：LiveBench suites 整包发布（7 轴在性价比池内覆盖恒 29），轴选择从不产生额外置 null——「不公平」在数据上无现实受害者。
- **失真层**：browser 低分与编码低分正相关（「强编码×未接浏览器」当前 0 例），真实偏差方向相反——browser 分位高×编码分位低的模型被抬进编程榜（MiniMax-M3.1-Flash coding 分位 36/browser 76、Kimi K3 15/64）。
- **语义层**：browser 是当年把 owner「终端操作」错落到浏览器轴的产物，锚错专项；LiveBench coding 轴经查证为 Python/算法类任务非前端榜（前端形态在 design 轴）；data_analysis（SQL/表格）是现成的后端栈证据；reasoning 与 coding 秩相关仅 0.448（n=29），通用轴非后端代理，拒混入。

## 结果（补记）

验收全绿：lint / prettier / coverage（门禁 92/85/90）/ build / 夹具三套 E2E 3×3/3；单测 32/32（codingIndices 用例按三轴新语义重写，browser 数据显式不参与）。
