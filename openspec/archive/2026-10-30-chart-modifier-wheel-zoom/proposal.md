# 前沿图修饰键滚轮缩放（⌘/Ctrl + 滚轮）

## 动机

前沿图当初关闭滚轮缩放，是因为 ECharts 6 的 RoamController 会在检查 per-zoom 标志之前就消费滚轮事件并 preventDefault，悬停图表时页面滚动被劫持；于是边界 capture `stopPropagation` 把滚轮全部挡在图表外（`src/Chart.jsx:83-90`），缩放只剩滑块与按钮。代价是图中密集区域（成本相近、积分接近的模型簇）无法快速放大细看。参考 Google 系图表的做法：普通滚轮保留页面滚动，按住修饰键（⌘ / Ctrl）滚动才缩放图表。调研确认可行——修饰键是明确的意图信号，且现有边界拦截恰好是控制「哪些滚轮事件到达 ECharts」的门控点；实现上不依赖 echarts 的 `'ctrl'` 绑定（6.1 的 `isAvailableBehavior` 直接映射原生 `ctrlKey`，不认 ⌘），在边界拦截里按 `ctrlKey || metaKey` 分流即可。附带收益：macOS 触控板捏合以合成 Ctrl 滚轮事件到达，自然获得「捏合缩放图表」。

## 涉及能力

- `ranking`：前沿图导航交互——新增修饰键滚轮缩放，拖拽平移从仅横轴扩展为双轴，放大/缩小/重置按钮跟随双轴。
- `share-link`：无参数变化。缩放窗口是临时视图状态，不写入 hash；仅显式声明以免与口径契约混淆。
- 触屏端：双指捏合从「无动作」变为缩放图表——pinch 通道与监听一直存在，只是此前被 per-zoom 标志关闭，本次随 `zoomOnMouseWheel: true` 一并启用（实现期源码核实，取代起草时「无变化」的预判）。

## 行为变化

- 图表画布上按住 ⌘ 或 Ctrl 滚动滚轮：成本轴与 PK 主积分轴以指针为中心同步缩放；该手势在画布上接管浏览器页面缩放（preventDefault），不叠加。指针在绘图区外（如横轴滑块上方）时不缩放、也不回落为页面缩放。
- 图表画布上触控板捏合：缩放图表而非页面（合成 Ctrl 滚轮事件与上一条同路）。
- 普通滚轮与触控板双指滚动：页面原生滚动，与现状完全一致；边界拦截保留。
- 拖拽平移从仅横轴扩展为双轴（缩放后需能平移回来）；`preventDefaultMouseMove` 保持。
- 放大/缩小/重置按钮作用于双轴，tooltip 去掉「横轴」字样；重置可用性按「任一轴偏离全范围」判断；横轴滑块继续只表示横轴窗口，不新增纵轴滑块（简单优先）。
- 图表下方说明文字改为「拖动平移，⌘/Ctrl + 滚轮缩放，滚轮用于页面滚动」，与实际行为一致。
- 对比页柱状图（`CompareChart.jsx`）无缩放需求，维持现状。

三个设计点采用推荐方案（owner 未另行否决即按此实施）：滚轮双轴联动、拖拽双轴、按钮双轴——散点图单缩横轴或单平横轴都会出现「缩放出不来」的半残状态。

## 兼容与影响

- 纯交互层改动，不触量化口径、分享契约或架构，不新立 ADR。
- 分享链接、CSV 导出、历史抽屉、评分与前沿判定均不受影响；缩放窗口不进入任何持久化状态。
- 已知坑文档同步改写为新契约：根目录 `AGENTS.md`「ECharts 滚轮」条目、`README.md` 图表交互节。`docs/three-board-workbench.md` 与 `docs/selection-efficiency.md` 是历史轮次的验收记录，各自记录当时行为，不改写历史。
- 实现机制备忘：边界监听需从 `passive: true` 改为 `false` 才能在修饰键分支 preventDefault（元素级 wheel 监听不默认 passive，处理器极轻，滚动性能无感）；inside dataZoom 的 `zoomOnMouseWheel` 改回 `true`，门控完全由边界拦截承担。
- 回滚：恢复 `zoomOnMouseWheel: false` 与无条件 `stopPropagation` 即回到现状，无数据迁移。

## 验收要点

- 单测：滚轮门控提取为纯函数，覆盖普通滚轮 / Ctrl / ⌘ / 合成捏合（ctrlKey）四种事件形态与 preventDefault、stopPropagation 分支；`zoomed` 状态按双轴判断。
- E2E：fixture 三套全绿；E2E 锚点类一律不动，说明文案如有断言同步更新。
- `npm run test:coverage`（行 92 / 分支 85 / 函数 90）与 `npm run build` 通过。
- 手动核对（4317）：普通滚轮滚动页面不受阻；⌘/Ctrl+滚轮双轴缩放且浏览器页面缩放不叠加；捏合缩放；拖拽双轴；滑块与按钮联动正常。

## 规格增补（合入时并入 `specs/ranking/spec.md`）

### Requirement: 前沿图修饰键滚轮缩放

普通滚轮始终保留页面滚动；按住 ⌘ 或 Ctrl 滚动滚轮、或在画布上捏合触控板时，图表以指针为中心同时缩放成本轴与 PK 主积分轴，该手势在画布上不触发浏览器页面缩放。

#### Scenario: 普通滚轮滚动页面

- **WHEN** 鼠标悬停图表画布且未按修饰键时滚动滚轮
- **THEN** 页面原生滚动，图表不缩放、不平移

#### Scenario: 修饰键滚轮双轴缩放

- **WHEN** 按住 ⌘ 或 Ctrl 在图表画布上滚动滚轮
- **THEN** 成本轴与 PK 主积分轴以指针为中心同步缩放，浏览器页面缩放不叠加；指针位于绘图区外时该手势不产生任何缩放

#### Scenario: 触控板捏合缩放

- **WHEN** 在图表画布上捏合触控板
- **THEN** 图表缩放而非页面缩放

#### Scenario: 触屏双指捏合同样缩放

- **WHEN** 触屏设备在图表画布上双指捏合
- **THEN** 图表缩放（捏合通道此前存在但被 per-zoom 标志关闭，随滚轮缩放启用）

#### Scenario: 拖拽平移双轴

- **WHEN** 图表处于缩放状态后拖拽画布
- **THEN** 成本轴与 PK 主积分轴窗口一起平移

#### Scenario: 按钮与滑块

- **WHEN** 使用放大、缩小或重置按钮
- **THEN** 三者作用于双轴；横轴滑块继续表示横轴窗口；任一轴偏离全范围时重置可用，重置后两轴回全范围

#### Scenario: 缩放窗口不进分享链接

- **WHEN** 用户缩放图表后复制分享链接
- **THEN** 链接与缩放前完全一致；缩放窗口是临时视图状态，不属于口径

#### Scenario: 说明文案如实

- **WHEN** 查看图表下方说明
- **THEN** 文案说明「拖动平移，⌘/Ctrl + 滚轮缩放，滚轮用于页面滚动」，与实际行为一致
